# Demonstration scenario (synthetic)

Reproducible narrative for the platform’s strongest workflow. Use fictional registrations such as `SEU/IS/21/ICT/A01`.

A. Admin creates batch, year, semester, subjects, lecturer assignment.  
B. Lecturer publishes a scanned-safe official resource.  
C. Student in that offering can download it; others cannot.  
D. Admin imports results including `E(CA)` matched by registration number + subject code.  
E. Student dashboard/CA list shows the incomplete condition.  
F. Admin opens an application window.  
G. Student submits; PDF/QR generate.  
H. Admin records physical verification then approves.  
I. Assigned lecturer sees the student.  
J. Lecturer schedules the CA.  
K. Calendar event + notifications appear.  
L. Reminder jobs exist for 7/3/1 day offsets.  
M. Later import updates the same registration+subject row (repeat/historical).  
N. GPA snapshot recalculates from official results.  
O. Academic history shows the updated official result.

Automated fragments exist in results, CA, communication, orchestration, and smoke tests. The full A–O path is not a single browser E2E recording.
